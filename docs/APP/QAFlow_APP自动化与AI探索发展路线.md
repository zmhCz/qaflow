# QAFlow APP 自动化与 AI 探索发展路线

> 版本：v1.0
> 制定日期：2026-07-18
> 适用范围：APP 自动化、语义元素库、页面地图、受控巡检、AI 探索与执行报告

## 1. 路线结论

QAFlow 当前不缺功能入口，主要短板是执行稳定性、结果可信度和使用流程。后续建设遵循以下顺序：

1. 先让目标巡检稳定、可重复、可诊断。
2. 再让页面地图和语义元素库形成可维护资产。
3. 然后让 AI 基于可信数据生成巡检计划和用例草稿。
4. 最后在风险护栏下逐步开放 AI 的受控执行能力。

近期不以继续增加页面和按钮为目标，也不让大模型直接控制手机。

## 2. 当前基础

平台已经具备以下能力：

- Android 真机连接、截图、UI 树、ADB 操作和日志采集。
- 语义元素截图框选、元素入库、复验、状态管理和用例编排。
- 探索任务、独立执行批次、目标结果和历史报告。
- 目标清单巡检、有限滑动、风险跳过、锚点恢复和证据采集。
- 页面节点、页面控件、跳转关系和语义候选沉淀。
- AI 报告分析、问题建议、下一轮目标和任务草稿生成。

当前功能完成度约为 70%，但稳定交付能力约为 50%～55%。主要差距是自动化回归测试不足、多设备验证不足、页面与执行器代码过重，以及核心指标尚未持续统计。

## 3. 短期路线：稳定可用

### 3.1 时间范围

未来 2～4 周。APP UI 改版完成前，优先建设与具体 UI 样式弱相关的执行底座，不集中扩充旧版页面的语义元素。

### 3.2 核心目标

形成一套可以稳定重复执行、结果可信、失败可解释的目标巡检闭环。

### 3.3 开发任务

1. 建立固定验收基线
   - 选择社区首页等 1～2 个稳定页面。
   - 每个页面配置 5～10 个目标控件。
   - 同一任务连续执行三次并自动生成一致性对比。

2. 补齐核心质量指标
   - 目标识别率。
   - 非目标控件误点击率。
   - 锚点恢复成功率。
   - 证据完整率。
   - 三次执行结果一致率。

3. 加固执行器
   - 将目标巡检与自由探索的流程和状态进一步隔离。
   - 完善点击、Switch、弹窗、列表和无页面变化场景的状态判定。
   - 找不到目标时停止当前目标，不点击无关控件。
   - 页面偏航时有限返回，恢复失败后停止并保留完整证据。

4. 补自动化回归测试
   - 目标解析和定位优先级测试。
   - 有限滑动和未找到处理测试。
   - 锚点恢复和重启重放测试。
   - 风险护栏测试。
   - 目标结果、报告和页面地图 API 测试。

5. 收敛使用流程
   - 创建任务只保留必要配置，高级参数默认折叠。
   - 报告首页只回答结论、问题和下一步操作。
   - 每个问题统一关联前后截图、点击范围、预期、实际和日志。
   - 修复乱码、重复内容和无明确操作目的的入口。

6. 控制技术债
   - 拆分探索报告页面中的报告、证据、复核和 AI 分析组件。
   - 拆分执行器中的设备操作、页面状态、目标定位、恢复和报告生成职责。
   - 建立可回滚的阶段版本，避免长期依赖未提交工作区。

### 3.4 短期验收标准

- 已配置目标识别率不低于 85%。
- 锚点恢复成功率不低于 95%。
- 非目标控件误点击率低于 5%，基准页面目标为 0。
- 高风险动作自动执行次数为 0。
- 每个目标证据完整率为 100%。
- 同一任务连续执行三次，结果一致率不低于 90%。
- 新用户能够按照页面引导完成“创建、执行、复核、生成下一轮”流程。

### 3.5 短期交付物

- 目标巡检验收任务和基准数据。
- 三次执行一致性报告。
- 核心执行器回归测试集。
- 精简后的探索报告和使用说明。
- 可标记为稳定基线的阶段版本。

## 4. 中期路线：资产闭环与团队试用

### 4.1 时间范围

未来 1～3 个月，APP UI 改版稳定后开始集中建设。

### 4.2 核心目标

把每次巡检产生的数据转化为可维护资产，降低人工录入语义元素和编排用例的成本，并具备小范围团队交付能力。

### 4.3 建设内容

1. 页面地图治理
   - 页面节点自动去重、合并和版本区分。
   - 维护页面业务名称、入口、父子关系和代表截图。
   - 支持页面地图版本差异和 UI 改版影响分析。

2. 语义元素库提效
   - 从页面地图批量生成语义候选。
   - 自动推荐业务对象、控件角色和规范名称。
   - 人工只确认业务语义和高风险边界，不重复填写技术定位信息。
   - 建立待确认、已验证、需调整和废弃的生命周期。
   - UI 改版后优先覆盖 P0/P1 页面，核心覆盖率达到 70%。

3. AI 规划达到 L1
   - AI 读取页面地图、目标结果、历史复核和覆盖缺口。
   - 生成下一轮目标清单、优先级和巡检草稿。
   - 过滤不存在、重复、高风险和不可执行动作。
   - 所有 AI 建议必须经过人工确认后保存。

4. 稳定路径转用例
   - 将高可信探索路径转换为自动化用例草稿。
   - 优先关联已验证语义元素，坐标定位仅作为待替换兜底。
   - 支持变量、公共组件、断言模板和数据驱动场景。

5. 报告与性能证据统一
   - 合并功能结果、性能曲线、logcat、截图和设备信息。
   - 明确区分 APP 缺陷、定位失败、环境异常和正常业务行为。
   - 提供缺陷摘要和企业微信机器人可消费的数据结构。

6. 小范围团队试用
   - 提供任务模板、页面模板和使用引导。
   - 选择 2～3 名测试人员试用并统计完成任务耗时、人工确认次数和失败原因。
   - 根据真实使用数据调整流程，不以新增功能数量作为主要成果。

### 4.4 中期验收标准

- 核心 P0/P1 页面地图可读、可维护且重复节点率低于 10%。
- 核心语义元素覆盖率达到 70%，已验证元素可跨主流 Android 设备复用。
- AI 生成目标中，可直接执行或仅需轻量修改的比例不低于 70%。
- 高可信探索路径能够转成可编辑用例草稿。
- 团队新用户可以在文档辅助下独立完成一次完整流程。

## 5. 长期路线：受控智能测试平台

### 5.1 时间范围

未来 3～12 个月，根据短期和中期指标决定是否进入下一阶段。

### 5.2 核心目标

让 QAFlow 从单机辅助工具演进为可扩展、可治理、可审计的智能测试平台，但不追求无边界的 AI 自动操作。

### 5.3 建设方向

1. AI 受控执行 L2
   - 平台生成安全候选动作，AI 只负责排序或选择。
   - 平台校验页面范围、动作预算、参数和风险等级后执行。
   - AI 不能生成任意坐标、ADB 命令或绕过风险护栏。

2. 有限自主探索 L3
   - 只在已批准页面、最大深度、最大时长和动作预算内运行。
   - 支持自动回滚、偏航终止和人工接管。
   - 高风险动作始终要求人工确认。

3. 跨任务学习 L4
   - 利用历史复核结果抑制重复误报。
   - 根据 UI 变更、定位失败和缺陷反馈调整目标优先级。
   - 学习结果必须可查看、可撤销、可按项目隔离。

4. 需求驱动自动化
   - 需求分析生成测试点和候选场景。
   - 页面地图判断场景是否具备可执行路径。
   - 语义元素库负责生成可维护步骤。
   - AI 生成用例草稿，人工审核后进入执行体系。

5. 跨平台与设备资源
   - 抽象统一设备接口，Android 使用 ADB/UIAutomator，iOS 使用 WebDriverAgent/Appium。
   - 业务页面和语义元素采用跨端业务标识，Android 包名与 iOS Bundle ID 作为平台实现配置。
   - 后续再建设设备调度、并发执行、占用锁、健康检查和远程节点。

6. 企业级治理
   - 权限、审批、审计、版本和项目隔离。
   - 任务队列、失败重试、通知和趋势分析。
   - 对外 API、企微通知和缺陷平台集成。
   - 模型调用成本、响应时间和建议采纳率监控。

### 5.4 长期验收方向

- AI 建议具备可解释证据和完整审计记录。
- 自动执行始终受页面边界、动作预算和风险护栏限制。
- Android 与 iOS 共用业务模型，但各自维护平台定位实现。
- 平台能够支持团队并发使用，而不是依赖单台开发电脑和人工守候。
- 自动化资产能够随 UI 版本变化进行影响分析和批量治理。

## 6. 总体技术方案

### 6.1 分层架构

```text
任务与策略层
  ├─ 目标巡检（默认）
  ├─ 自由探索（高级）
  └─ 回归用例执行
        ↓
执行编排层
  ├─ 任务调度与执行批次
  ├─ 目标队列与动作预算
  ├─ 风险护栏
  └─ 锚点恢复与失败终止
        ↓
设备适配层
  ├─ Android：ADB + UIAutomator + 截图
  └─ iOS：WebDriverAgent/Appium（后续）
        ↓
识别与判定层
  ├─ 语义元素定位
  ├─ 文本、resource-id 和结构定位
  ├─ 归一化 bounds/坐标兜底
  └─ 页面、弹窗、Switch、列表状态判定
        ↓
资产与证据层
  ├─ 页面地图
  ├─ 语义元素库
  ├─ 前后截图与点击范围
  ├─ UI 树、logcat 和性能数据
  └─ 执行报告与人工复核规则
        ↓
AI 决策层
  ├─ 报告分析 L0
  ├─ 巡检计划生成 L1
  ├─ 受控动作建议 L2
  ├─ 有限自主探索 L3
  └─ 跨任务学习 L4
```

### 6.2 核心数据模型

- `AppExplorationTask`：可复用任务定义和安全配置。
- `AppExplorationRun`：每次真实执行批次，不覆盖历史结果。
- `AppInspectionTargetResult`：每个目标的状态、证据和失败原因。
- `AppPageNode`：按项目、应用、平台和版本隔离的页面节点。
- `AppPageElement`：页面内控件快照和语义候选。
- `AppPageTransition`：页面之间的触发动作、成功率和可信度。
- `AppElementConfig`：正式语义元素及多平台定位策略。

### 6.3 定位策略

目标定位按以下优先级执行：

1. 已验证语义元素。
2. 可见文字和 `content-desc` 精确匹配。
3. `resource-id` 和控件结构匹配。
4. 文字模糊匹配和可点击父容器提升。
5. 归一化 bounds 和坐标兜底。
6. OCR 或图像识别仅作为有限补充。

每次定位必须记录实际命中的策略，便于统计稳定性和批量治理失效元素。

### 6.4 页面状态判定

页面变化不能只依赖 Activity 或整页截图，需要组合以下信号：

- Activity、Window 和弹层变化。
- 稳定控件结构与页面语义指纹变化。
- `checked`、`selected`、`enabled` 和文本状态变化。
- 列表数量、目标区域和局部截图变化。
- Toast、异常弹窗、崩溃和 ANR 日志。

动态昵称、时间、计数和列表内容需要在页面指纹中降权或忽略。

### 6.5 AI 安全边界

- AI 只输出平台定义的结构化目标或动作。
- 平台负责定位、参数校验、风险判断和实际设备操作。
- 删除、支付、注销、解散和提交订单等动作默认禁止。
- 未知页面、无证据坐标和超出动作预算时立即停止。
- AI 建议、人工修改和最终执行结果全部保留审计记录。

### 6.6 工程质量方案

- 后端按执行器、设备适配、定位、状态、证据和报告拆分模块。
- 前端按任务创建、处理台、目标矩阵、页面证据、复核和 AI 分析拆分组件。
- 核心规则使用单元测试，任务闭环使用 API 集成测试，关键页面使用真机基准回归。
- 每个阶段必须形成可回滚版本和验收记录，再进入下一阶段。
- 产品指标以稳定率、人工成本和问题定位效率为主，不以页面数量和功能入口数量为主。

## 7. 优先级与边界

### P0：当前必须完成

- 目标巡检三次一致性验收。
- 目标定位、状态判定、锚点恢复和证据链稳定。
- 核心回归测试与失败诊断。
- 报告流程精简和代码职责拆分。

### P1：P0 稳定后推进

- 页面地图治理和 UI 版本差异。
- 语义元素候选批量确认。
- AI 下一轮计划质量约束。
- 稳定路径转用例和性能报告联动。

### P2：有团队使用需求后推进

- iOS 执行器。
- 设备资源池和分布式节点。
- 企微、缺陷平台和持续集成体系。
- AI L2/L3 受控执行。

## 8. 暂不建设

- 大模型实时裸控手机。
- 无边界随机点击或无限滑动。
- AI 未经确认直接发布语义元素或正式用例。
- 为即将改版的旧 UI 大规模维护语义元素。
- 在单机使用阶段提前建设复杂设备资源调度系统。

## 9. 路线检查机制

每两周进行一次路线复核，只回答以下问题：

1. 当前阶段的验收指标是否已经达到。
2. 新需求是否直接提升稳定性、人工效率或结果可信度。
3. 是否在上一阶段未验收前提前建设上层能力。
4. 是否增加了新的人工理解成本或维护入口。
5. 是否形成了可验证、可回滚的阶段版本。

若第 1 项未完成，原则上不进入下一阶段；若新需求不能改善核心指标，则进入待办池，不立即开发。
