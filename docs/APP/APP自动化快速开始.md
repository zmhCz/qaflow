# APP 自动化快速开始

## 适用场景

当前这套平台最适合这样使用：

- 平台负责管理项目、包名、设备、元素、用例、套件、报告
- 具体的移动端自动化能力，围绕 Android 设备和 APP 场景展开
- 推荐第一条先做最小闭环场景，而不是一上来铺很多页面

针对当前项目，建议先围绕下面这个应用开始：

- 应用名称：示例社区 APP
- 应用包名：`com.example.qaflow.demo`
- 推荐首条场景：账号密码登录成功 / 验证码登录成功

## 推荐起步顺序

### 1. 项目管理

进入 `APP自动化 -> 项目管理`

建议使用项目：

- 项目名称：`社区APP自动化`
- 项目描述：社区 APP 登录、社区创建、社区解散、取消关注、退出登录等核心回归场景

## 2. 包名管理

进入 `APP自动化 -> 包名管理`

确认已存在：

- 应用名称：`示例社区 APP`
- 应用包名：`com.example.qaflow.demo`

## 3. 设备管理

进入 `APP自动化 -> 设备管理`

建议按这个顺序操作：

1. 点击“刷新设备”
2. 确认真机已被发现
3. 锁定一台测试设备
4. 后续所有执行都优先固定用这一台设备

这样可以避免多人或多任务执行时设备冲突。

## 4. 元素管理

进入 `APP自动化 -> 元素管理`

第一批建议沉淀这些元素：

- 手机号输入框
- 密码输入框
- 验证码输入框
- 登录按钮
- 协议勾选框
- 滑块区域
- 首页强校验元素

建议优先把“登录链路”相关元素录完整，再做社区业务元素。

## 5. 用例编排

进入 `APP自动化 -> 用例编排`

第一条场景建议只做最小闭环：

1. 启动 APP
2. 进入登录页
3. 输入手机号
4. 输入密码或验证码
5. 点击登录
6. 处理滑块验证
7. 校验进入首页

不要一开始就把创建社区、解散社区、取消关注全部塞进第一条场景里。

## 6. 测试用例

进入 `APP自动化 -> 测试用例`

执行前建议确认：

- 已选设备
- 已选应用包
- 对应用例已保存

推荐的执行节奏：

1. 先单条执行登录场景
2. 登录稳定后，再补退出登录
3. 然后再补创建社区、解散社区
4. 最后再组装回归套件

## 7. 测试套件

进入 `APP自动化 -> 测试套件`

推荐拆成独立用例后再组套：

- 登录
- 退出登录
- 创建社区
- 解散社区
- 取消关注社区

推荐的第一个套件：

- `登录 -> 退出登录`

推荐的第二个套件：

- `登录 -> 创建社区 -> 解散社区 -> 取消关注社区 -> 退出登录`

## 当前最实用的落地方式

如果你已经有现成的 `app-ui-auto` 自动化框架，推荐这样协同：

- 平台负责管理资产和执行入口
- 现有自动化框架负责真正执行

也就是：

- 平台里维护项目、设备、包名、元素、用例、套件
- 底层依然复用你已经稳定的登录、滑块、验证码、首页断言逻辑

这样是当前风险最低、见效最快的接入方式。

## 当前阶段的最小目标

先只达成这一件事：

- 在平台里完成“社区 APP 登录成功”这一条用例的管理和执行闭环

当这条闭环稳定以后，再继续扩展：

- 登录 -> 退出登录
- 登录 -> 创建社区
- 登录 -> 解散社区
- 登录 -> 创建社区 -> 解散社区 -> 取消关注社区 -> 退出登录
